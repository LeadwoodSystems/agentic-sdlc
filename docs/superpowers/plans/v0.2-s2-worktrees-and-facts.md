## Approach

**Merged-branch detection.** The hardening doc proposes `git cherry` as the no-GitHub
fallback; measurement above shows it does not work, because a squash-merge produces one
commit whose patch-id equals the *combined* diff. Use instead:

1. **Primary:** `gh pr list --state merged --head <branch> --json number` — authoritative,
   and exactly what `finish-sprint.js` already assumes has happened.
2. **Fallback:** `git diff --quiet <trunk> <branch>` — exit 0 ⇒ the branch's content is
   already in trunk. **Documented failure mode:** once trunk advances past the merge the
   trees diverge and this returns "not merged" — a false *negative*, which is the safe
   direction for a report-only audit and a gate that errs toward blocking.

Live in one place (`lib/branch-status.js`) consumed by both `gh-hygiene.js` and
`new-sprint.js`, which today hold the same broken test in two places.

**Reuse (do not re-derive):** `lib/exec.js` `run()` injection seam (trims output, no
stdin) · `safeCheck` (`gh-hygiene.js:125-131`) · the marker injection guard
(`checkpoint-hooks.js:41-46`) · `test/helpers/fixture-repo.js` `makeFixtureRepo` ·
`lib/profile-block.js` as the reference shape for CRLF-tolerant upsert.
