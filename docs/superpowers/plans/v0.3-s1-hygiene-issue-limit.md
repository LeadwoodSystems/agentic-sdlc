**Goal:** Make `gh-hygiene`'s untriaged-issue check see every open issue, and make it
structurally incapable of silently under-reporting when it cannot.

**Architecture:** One named constant `ISSUE_LIST_LIMIT` feeds both the `--limit` flag and the
cap detector, so the bound and its detector cannot drift. `findUntriagedIssues` returns
`{ findings, truncated }` instead of a bare array, and the `untriagedIssues` renderer appends
a TRUNCATED notice — copying `findStaleRemoteBranches`, which solved this identical problem
in this identical file.

**Tech Stack:** Node core only, `node:test` + `node:assert`, the `gh` CLI behind the existing
injected `runner` seam.

## Global Constraints

- **Zero dependencies.** Node core only; no `package.json`, no install step (`CLAUDE.md#zero-dependencies`).
- **Runner injection preserved.** Every function that shells out keeps `{ runner = run }` (`CLAUDE.md#runner-injection`).
- **No configuration knob for the limit.** Not an option, env var, or CLI flag — #57's governing sentence is "no configuration should be able to make the audit under-report in silence".
- **Exact constant value:** `ISSUE_LIST_LIMIT = 1000`.
- **Exact notice text:** `` `TRUNCATED: hit the ${ISSUE_LIST_LIMIT}-issue limit, list may be incomplete` ``
- **Exact separator:** `' · '` (U+00B7, matching `staleRemoteBranches`).
- **`main()` is not touched.** Truncation must NOT set `process.exitCode = 1`. In this script findings never fail the audit; only a broken check does (`:415-417`). Truncation is a degraded result, not a failed check — leave that rule alone rather than carving an exception into it.
- **CRLF.** `core.autocrlf` is on; convert any written file with `[System.IO.File]::WriteAllText` before staging (`CLAUDE.md` conventions).
- **Line references** in this plan are against `gh-hygiene.js` / `gh-hygiene.test.js` at `52db4f7`. Re-locate by content if they have shifted.

## Context (why)

`findUntriagedIssues` passes no `--limit`, so `gh` applies its default of 30. Measured at
`5b0009d`: 46 open issues, 39 genuinely unprofiled, **30 reported**, nine silently omitted —
and the output reads as a complete worklist. `/profile-issue` consumes exactly this list, so
nine issues cannot be picked up through the intended flow. The fix must remove both the
under-count and the silence.

## Scope

- **In:** `findUntriagedIssues`, the new `ISSUE_LIST_LIMIT` constant, the `untriagedIssues`
  entry in `HYGIENE_CHECKS`, and the affected tests.
- **Out:** every other hygiene check; what counts as untriaged (`PROFILE_LABEL_PREFIXES` is
  correct); **#37**'s non-executable-issue-kind exemption, which lands in this same function
  next and deliberately follows this sprint so it reasons about a known-complete input set;
  the pre-existing milestone OUT OF SYNC noise.

## Approach

Three tasks. Task 1 raises the bound; task 2 adds cap detection, the return shape and its
renderer together (a reviewer cannot sensibly approve the shape without the renderer, and
splitting them would leave `format` reading `v.length` off an object and rendering `none` for
every backlog); task 3 is the offered mutation manifest.

**File structure — nothing new but the manifest:**

| File | Responsibility | Change |
|---|---|---|
| `scripts/asdlc/gh-hygiene.js` | the audit's checks and their rendering | modify `:193-216`, `:358-363`, `:420-432` |
| `scripts/asdlc/test/gh-hygiene.test.js` | that module's unit tests | +3 tests, 7 ported assertions |
| `docs/mutation-manifests/v0.3-s1.json` | mutation evidence for cited tests | create |

**Reuse, don't invent:** `findStaleRemoteBranches` (`:326-345`) is the pattern for both the
two-part return and the ` · `-joined "what I could not see" rendering. `HYGIENE_CHECKS` is
already exported and already read by `test/command-prose.test.js`, so tests reach the
renderer via `HYGIENE_CHECKS.find((c) => c.key === 'untriagedIssues').format(...)` rather than
by testing the untested `main()`.

test('findUntriagedIssues reports a full page as possibly truncated', async () => {
  const { dir, cleanup } = await makeFixtureRepo();
  try {
    // Every stub issue is fully profiled, so findings comes back empty. That is
    // the dangerous case on purpose: a bare "none" reads as a clean backlog when
    // the real reason is that nothing past the cap was ever looked at.
    const full = Array.from({ length: ISSUE_LIST_LIMIT }, (_, n) => ({
      number: n + 1,
      labels: [{ name: 'complexity/low' }, { name: 'risk/low' }, { name: 'execution/fast' }],
      milestone: { title: 'v0.3' },
    }));
    const result = findUntriagedIssues(dir, { runner: () => JSON.stringify(full) });
    assert.equal(result.truncated, true);
    assert.deepEqual(result.findings, []);

    const check = HYGIENE_CHECKS.find((c) => c.key === 'untriagedIssues');
    assert.match(check.format(result), /TRUNCATED/);
  } finally {
    cleanup();
  }
});

test('findUntriagedIssues stays quiet about truncation on a short page', async () => {
  const { dir, cleanup } = await makeFixtureRepo();
  try {
    const stubRunner = () => JSON.stringify([{ number: 1, labels: [], milestone: null }]);
    const result = findUntriagedIssues(dir, { runner: stubRunner });
    assert.equal(result.truncated, false);

    const check = HYGIENE_CHECKS.find((c) => c.key === 'untriagedIssues');
    assert.doesNotMatch(check.format(result), /TRUNCATED/);
  } finally {
    cleanup();
  }
});

- [ ] **Step 3: Write minimal implementation**

Replace the `return findings;` at `:215` with:

```js
  // A full page back means gh may have had more to give. `>=` rather than `===`:
  // on an exactly-at-the-limit backlog this reports possible truncation when the
  // list may in fact be complete. A false alarm is recoverable; the silent
  // version is the defect being fixed, so the bias goes this way deliberately.
  return { findings, truncated: issues.length >= ISSUE_LIST_LIMIT };
```

Replace the `untriagedIssues` entry's `format` (`:362`) with:

```js
    format: (v) => {
      const parts = [v.findings.length ? v.findings.map((i) => `#${i.number} (${i.reason})`).join(', ') : 'none'];
      // Same reasoning as staleRemoteBranches above: report what could not be
      // seen rather than letting a bounded list read as the whole list.
      if (v.truncated) parts.push(`TRUNCATED: hit the ${ISSUE_LIST_LIMIT}-issue limit, list may be incomplete`);
      return parts.join(' · ');
    },
```
