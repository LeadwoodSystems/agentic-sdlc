## Global Constraints

- **`#zero-dependencies`** — Node core only. No `package.json`, no lockfile, no install step.
- **`#runner-injection`** — every function that shells out takes an injected runner. Task 4
  extends the same idiom to a *path*: `createSprint` gains `referenceTemplatePath` so a test
  can point the middle rung somewhere other than the real plugin tree.
- **`core.autocrlf` is on** — files on disk are CRLF. Never round-trip a source file through a
  shell; use Read/Edit/Write, then verify. `Write`/`Edit` emit LF in this repo — if `git add`
  warns `LF will be replaced by CRLF`, repair with
  `[System.IO.File]::ReadAllText`/`WriteAllText` before staging. This sprint is *about* line
  endings; a plan file committed with mixed endings would be its own counterexample.
- **Shell:** PowerShell is canonical on this machine. The Bash tool is retired here.
- **Marker spans** in `CLAUDE.md` are machine-owned — never hand-edit between the markers.
- **`#ports-are-prose`** — countable facts go in `.asdlc/facts.json`, not into prose.

## Context (why)

The v0.2-s5 checkpoint found `checkpoint-hooks.js` writing LF into CRLF files: `CLAUDE.md`
went CRLF=161/LF=0 → CRLF=159/LF=2, `STATUS.md` LF=0 → LF=1. `autocrlf` normalises the index
so nothing is corrupted, but `CLAUDE.md`'s Conventions rule says "anything that rewrites a
document must detect and preserve the dominant line ending" and names only two libs.
`checkpoint-hooks.js` is the third marker-span owner and honours neither half of it.

Loading context for this sprint turned up a second, larger instance of the same shape.
`CLAUDE.md` states this repo dogfoods its own methodology. Measured against
`~/.claude/commands/`: `asdlc-hygiene.md` and `profile-issue.md` are **not installed**;
`bootstrap-asdlc.md` and `checkpoint.md` differ by 49 lines each; `sprint.md` by 15. The
installed copies date from `092bcdd` (initial commit). `/sprint` and `/checkpoint` in this
repo have been running prose that predates every fix made to them — this sprint's own `/sprint`
invocation skipped the `new-sprint.js` gate step because the installed copy has no such step.
`.claude-plugin/marketplace.json` and `plugin.json` already exist and point at `./`; the plugin
was simply never enabled, and hand-copies were used instead.

The remaining three are the cheap-but-real items the v0.2-s5 handoff named. All five share one
failure mode: a claim nothing derives and nothing checks.

```js
// Total LF minus CRLF pairs = the LFs that are NOT part of a CRLF. Counting this
// way rather than with a lookbehind keeps the intent readable: a CRLF document
// that gained a bare \n is exactly what `core.autocrlf` hides from `git diff`.
function bareLfCount(text) {
  const lf = (text.match(/\n/g) || []).length;
  const crlf = (text.match(/\r\n/g) || []).length;
  return lf - crlf;
}

      '**Current state:** old',
```

```js
function appendStatusEntry(cwd, { sprintId, date, summary, handoffRelPath }) {
  const statusPath = path.join(cwd, 'docs/STATUS.md');
  fs.mkdirSync(path.dirname(statusPath), { recursive: true });

  // An EXISTING file's own ending is authoritative — appending LF to a CRLF
  // document is what produced the mixed endings this replaces. A file created
  // here has nothing to detect, so it gets LF and autocrlf normalises it.
  const existing = fs.existsSync(statusPath) ? fs.readFileSync(statusPath, 'utf8') : null;
  const eol = existing === null ? '\n' : detectEol(existing);
  if (existing === null) {
    fs.writeFileSync(statusPath, STATUS_HEADER.replace(/\n/g, eol));
  }

  // Sanitize all interpolated fields: replace CR/LF with spaces to maintain the
  // one-line-per-entry invariant (a bare \r, not just \r\n, also renders as a
  // line break in Markdown and must be stripped).
  const sanitizedSprintId = sprintId.replace(/[\r\n]/g, ' ');
  const sanitizedSummary = summary.replace(/[\r\n]/g, ' ');
  const sanitizedHandoffRelPath = handoffRelPath.replace(/[\r\n]/g, ' ');
  const sanitizedDate = date.replace(/[\r\n]/g, ' ');

  const line = `- ${sanitizedDate} **${sanitizedSprintId}** — ${sanitizedSummary} — [handoff](${sanitizedHandoffRelPath}) — status: awaiting-merge${eol}`;
  fs.appendFileSync(statusPath, line);
}
```

```js
const CURRENT_STATE_MARKERS = makeMarkers('asdlc:current-state:auto');

function updateClaudeMdPointer(cwd, summaryLine) {
  const claudeMdPath = path.join(cwd, 'CLAUDE.md');
  const content = fs.readFileSync(claudeMdPath, 'utf8');

  // upsertBlock APPENDS an absent span. That is right for the facts block, which
  // may legitimately be created at the end of a file, and wrong here: the
  // current-state pointer's POSITION in CLAUDE.md is part of its meaning, and
  // silently re-homing it to the bottom is worse than refusing. So absence is
  // checked here rather than delegated.
  if (!findBlock(content, CURRENT_STATE_MARKERS).found) {
    throw new Error(
      `CLAUDE.md is missing the ${CURRENT_STATE_MARKERS.start} marker — cannot safely update the pointer.`,
    );
  }

  // The injection guard is assertNoMarkerText, inside upsertBlock — a payload
  // containing the marker text throws before anything is written, so the file
  // is not corrupted on this run or the next. The hand-rolled copy that used to
  // live here is gone; this is the whole reason marker-block.js exists.
  fs.writeFileSync(
    claudeMdPath,
    upsertBlock(content, CURRENT_STATE_MARKERS, `**Current state:** ${summaryLine}`),
  );
}
```

## Key decisions & trade-offs

- **`asdlc-lint.js` is not extended.** It argues for a one-file scope at `:206-218` and names
  cross-file disagreement as explicitly out of bounds. Adding disk-derived checks would make
  that paragraph false and turn a narrow smoke detector into a general repo linter.
  `facts.js` is not the alternative either — `summarize()` caps a fact at one line / 120 chars,
  so a 15-name list truncates. **Deleting the enumerations removes the failure mode instead of
  gating it**, which is the v0.2-s4 derive-don't-enumerate argument taken to its end.
- **No `plans/_TEMPLATE.md` is added to this repo.** A copy of `references/plan-template.md`
  is a second file that drifts; the resolution order gives the same result with nothing to
  drift. Consumers keep the bootstrap-written copy and are unaffected.
- **`upsertBlock`'s append-when-absent is deliberately not inherited.** The current-state
  pointer's position in `CLAUDE.md` carries meaning, so `updateClaudeMdPointer` keeps its own
  `found` check and refuses. Delegating everything would have been tidier and wrong.
- **A newly created `STATUS.md` gets LF, not `os.EOL`.** Detecting an ending requires content;
  guessing from the host OS would impose a house style on repos that do not use one, and
  `autocrlf` normalises LF on checkout anyway.
- **`profile-block.js` stays unmigrated.** Its fence guarding is behaviour `upsertBlock` does
  not reproduce. Named in `marker-block.js`'s note so the next reader knows it is a decision.
- **Task 2 is done early on purpose**, so this sprint's own `/checkpoint` and `/handoff` run
  the real prose. It is also the riskiest step to sequence late: if the plugin does not load,
  everything after it would have been built against commands that are about to change.

## Risks / open questions

- **The plugin loads commands from the working tree.** Once enabled, a half-edited
  `commands/*.md` on a sprint branch is live in the session. That is the dogfooding working as
  intended, but it means a broken command is a broken session — restore from
  `~/.claude/commands-backup-092bcdd` if `/checkpoint` becomes unusable mid-sprint.
- **Enabling a plugin may need a session reload**, which loses conversation context. Do Task 2
  at a clean point, with the plan committed.
- **`appendStatusEntry` still appends blindly to a file not ending in a newline.** Only these
  scripts write `STATUS.md` and both terminate their output, so it cannot happen today. Left
  alone rather than fixed speculatively; if a hand-edit ever causes it, that is the finding.
- **`FAILING_CONCLUSIONS` is a closed set against an API that can add members.** A new GitHub
  conclusion would be silently ignored rather than reported. That is the correct direction for
  a check whose false positives cost trust, but it is a real trade and belongs in the handoff.
- **Deleting an enumeration removes a map some readers used.** Mitigated by pointing at the
  directory, which is always right. If it proves too thin in practice, the answer is a
  generated list, not a hand-maintained one.
- **No CI in this repo**, so the suite is the only gate.
