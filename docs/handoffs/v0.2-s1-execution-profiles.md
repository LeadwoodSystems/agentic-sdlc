## Key decisions & trade-offs

- **Class labels, never model names**; model resolves via `.asdlc/policy/execution-classes.yaml`.
- **JSON payload, YAML config.** Markers unversioned — a versioned marker stops matching
  its own v1 span and appends a duplicate.
- **Assessment prose is now fence-guarded** (`2475e6d`). `upsertProfile` checked the JSON
  payload for ``` but not the prose. The prose is the likelier offender — it quotes files
  and config — and the worse one: it is emitted *above* the JSON fence inside the same
  marker span, so a fenced block there is the first one `parseProfile` finds. It returned
  that object **silently, with no error**. A dispatcher would route on prose.
- **Publishing was scripted, not hand-run.** Two throwaway scratchpad scripts did the
  loop; they are gone with the session. Worth ~40 lines to rebuild in `scripts/asdlc/`:
  read the live body → `upsertProfile` → **re-`parseProfile` the result and abort if it
  won't round-trip** → `gh issue edit --body-file` → reconcile all three label families in
  one call, removing stale ones. The pre-flight re-parse is what caught the fence bug.

## Deferred / known gaps

- **`assessed_at_sha` cannot express a dirty tree.** Eight of this session's profiles were
  assessed against `f834f2a` *plus uncommitted edits* — a state with no SHA. GAW then
  squash-merged mid-pass, and `resolution.py` differs by 41 lines between `f834f2a` and
  `11ffe0e`, so those citations are actually **closer to the SHA they don't cite**. The
  prose says "working-tree" (the brief required it) but the machine-readable field can't.
  Add `assessed_tree_dirty: true`, or forbid the SHA when the tree is dirty. Real incident,
  not hypothetical.
- **The `execution/*` axis is collapsed and prose could not fix it.** Milestone-wide:
  planning 18 `standard`/10 `deep`/5 `fast`, review 20 `deep`/12 `standard`/1 `fast` — both
  discriminate. Implementation is **27 `standard` / 5 `fast` / 1 `deep` (82%)**. Mid-pass I
  added an instruction requiring assessors to argue *both* why not `fast` and why not
  `deep`; all 8 issues after it still returned `standard`. Reasoning quality improved
  (see #183), distribution did not. Either `standard` genuinely fits a milestone that is
  one long refactor sequence, or `default_routing` anchors the axis beyond prose's reach.
  **This matters for Sprint 3:** `execution/*` records implementation, the phase where cost
  concentrates, and it is the least informative of the three labels. A feedback loop
  comparing estimates to actuals will learn least where it matters most.
- **Sprint 3 (feedback loop) not started**, still gated: `.asdlc/execution-log.jsonl`,

  tier, `.gitattributes` `*.jsonl merge=union`. Plan:
  `~/.claude/plans/docs-asdlc-issue-modernization-pass-md-clever-pike.md`.
- **`checkpoint-hooks.js` has no PowerShell port** — GAW runs `.ps1`; ~5 lines when Sprint 3 lands.

## Findings handed back to GAW

**Every one of the 16 issues profiled this session contained at least one materially false
statement** — not just stale line numbers, but wrong mechanisms, wrong counts, and steps
already shipped. `/profile-issue` recommends `/verify-issue` first on stale or
architectural issues; at this rate the recommendation is too weak. Consider making a
premise check mandatory. Highest-value items, each on the issue itself:

- **#183 describes half its own defect.** When one line prices and another conflicts,
  `quote_worker.py:517` sees non-empty `priced_lines`, so a quote is built that **silently
  drops the conflicting line with zero open flags shown**. The fix as written leaves the
  worse bug in place.
- **#28 was closed by accident.** `823fae8` (docs-only) contains the literal `closes #28`
  inside a parenthetical describing #191; GitHub parsed it. Verified directly. The stub is
  live at `dev_erpnext.py:92-105`. Reopen before sprinting #191.
- **#178's abstraction does not hold at n=2.** `enquiry_worker` has real content for 2 of
  L6a's 6 contract functions; the port is *additive*, judged against a "no regression" bar
  on a `type/refactor` issue. Its reuse-ratio criterion **already passes at 81.6%** because
  the denominator isn't pinned.
- **`enquiry_worker`'s instrumentation gap is systemic, not per-issue.** Zero `stage_trace`,
  zero `observability.record`, zero `finish_job` (verified: 0/0/0 vs quote's 4/4/5). It
  blocks acceptance criteria on **#178, #179, #188 and #190** independently.
- **`docs/v0.13-build-sequence.md:104` folds #173 into #183 unsoundly** — two independent
  assessments converged on this. Only the seed edit rides along.
- **Two "green CI" signals are vacuous.** #203's test cannot fail in CI (no `:8000` server,
  so it always skips); #192's corpus tier doesn't run on PRs (`ci.yml:98`).
- **Under-counting is systemic:** #191 named 0 call sites and has 17; #186 implied a
  contained extraction and has 19 (+13 frontend helpers); #184 named 0 and has 11; #183
  cited 2 and has 11; #169 named 1 and has 4.
- **No tenancy hole in #179** — all nine models org-scoped, all readers filter. A negative
  result worth recording; the #200/#202 cross-tenant finding does not generalise.
