## Key decisions & trade-offs

- **Class labels, never model names.** `model/*` from the brief was dropped; the model
  resolves via `.asdlc/policy/execution-classes.yaml`, so a lineup change is a one-line
  config edit rather than a backlog relabel. `risk/{low,medium,high}` deliberately matches
  the v2 control plane's `work-contract.schema.yaml` enum.
- **Config defaults are GAW's own convention, read off its handoffs** — not invented.
- **JSON payload, YAML config.** Anything a script parses is JSON; YAML is agent-read only.
- **Markers unversioned** — a versioned marker stops matching its own v1 span and appends
  a duplicate, the exact failure markers exist to prevent.

Two schema changes were forced by the real run and are committed (`01fd566`, `f9484fe`):

1. **`assessed_at_sha` is required.** GAW moved twice mid-session (`d230764` → `f834f2a`);
   line citations differ by ~15 between HEAD and a dirty tree. Two agents disagreed on the
   same call sites for this reason alone.
2. **The inflation failure mode is documented.** Uncalibrated, planning returned `deep` on
   **8 of 9** issues. One counter-instruction paragraph moved the next batch to 1 of 4.
   Same rubric, same model. An axis that always returns one value carries no information —
   `/profile-issue` now prints the per-phase distribution after each batch.

Current distribution across the 17: planning 3 `fast` / 7 `standard` / 6 `deep`;
implementation 4 / 11 / 1; review 8 `standard` / 8 `deep`.
