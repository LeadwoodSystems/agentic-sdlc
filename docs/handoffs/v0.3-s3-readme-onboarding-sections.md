## Key decisions & trade-offs

- **No test for #21.** Its acceptance criteria are semantic (is a step misdescribed?), not
  machine-checkable. The gate is Task 6 Step 4's independent, blind, primary-source re-walk
  — and it earned its keep: it caught the one wording defect two prior passes missed.
  Recorded rather than papered over (`task-7-brief.md`).
- **The `text`-fence language tag stays unique to the diagram.** The walkthrough's command
  block uses a bare ` ``` ` fence, not ` ```text `, specifically so `FENCEPLAIN`'s anchor
  and the existence assertion still mean "the #18 diagram is present," not "some text block
  is present." Verified at 1 occurrence after every task that touched `README.md`
  (`task-2-report.md`, `task-3-report.md`, `task-4-report.md`).
- **`.length` measures UTF-16 code units, not display width.** Correct for the arrows
  (U+2193, U+2192) and em dash (U+2014) in scope; wrong for CJK, emoji, or any surrogate
  pair. Left as a documented limit, not fixed — `#zero-dependencies` rules out pulling in a
  width-aware library for a limit nothing in scope triggers.

## Incidents worth carrying forward

1. **The plan's Task 5 step order was impossible.** It specified write manifest → dry-run →
   real run → commit. `scripts/asdlc/mutate.js:266-282` calls `assertCleanTree()`
   unconditionally, ahead of the `--dry-run` branch, so an untracked manifest file blocks
   even a dry run — confirmed by the actual refusal:
   ```
   Refusing to run with uncommitted changes:
   ?? docs/mutation-manifests/v0.3-s3.json

   Commit or stash them, or pass --allow-dirty.
   ```
   The implementer committed the manifest first and disclosed the reordering in
   `task-5-report.md`; a reviewer read `mutate.js` and confirmed the reorder was forced and
   cost no evidence (`progress.md`: "Task 5: note (not a defect)"). **General lesson:** plan
   steps must be written against a tool's actual preconditions, not an assumed order.

2. **The plan mandated a factual error, and only the blind re-walk caught it.** The plan's
   own Task 4 Step 2 text credited `/checkpoint` with producing "a staged commit."
   `/checkpoint` stages changes; it does not create a commit
   (`commands/checkpoint.md:45-47`), and the README's own callout eight lines below already
   said so. Task 4's author pass and its reviewer both passed the row CONFIRMED without
   testing that specific phrase. Task 6 Step 4's independent re-walk — done blind, before
   reading any prior report — found it and flagged it as a new finding
   (`task-6-report.md`, Concerns §1). It was escalated as a plan conflict rather than
   silently patched, because the wording traced back to the plan itself
   (`progress.md`: "Task 6... Plan-mandated..., escalated to the human per the plan-conflict
   rule"). **RULING (human, 2026-08-08):** "fix it - the cell becomes staged changes, not a
   staged commit. #21 exists to stop exactly this misdescription." Fixed in `eb2c20a`, one
   cell, one insertion / one deletion. **General lesson:** a review pass that only checks
   whether cited facts exist, and not whether the exact wording matches, can pass a
   contradiction straight through — which is why the re-walk had to be independent and
   blind rather than a second look at the same table.

3. **The plan's citation for `finish-sprint.js` did not support its claim.** The plan cited
   `commands/checkpoint.md:51-53`, which says only that `finish-sprint.js` runs "once the PR
   merges" — it establishes timing, not what the script produces. The implementer caught
   this during Task 4 and proposed `commands/asdlc-hygiene.md:72-73`, which covers 2 of the
   3 sub-claims (worktree retirement, branch deletion) but not the STATUS flip. A reviewer
   found the correct anchor: `README.md:206`, the pre-existing Architecture-and-layout table
   entry — `finish-sprint.js   post-merge worktree removal, status flip, branch cleanup` —
   which matches all three sub-claims near-verbatim and predates this sprint. The README's
   walkthrough *text* was true throughout; only the evidence trail was weak, and it now
   resolves to `README.md:206` (`task-4-report.md` Fix round 1, "Report citation trail
   corrected"; `progress.md` "Task 4: minor (deferred)").

   children.

   assumed. Worth revisiting if `epic-without-open-sub-issues` ever fires in anger.
9. `openParents` uses `.filter(Boolean)`, so a parent numbered `0` would be dropped. GitHub
   issue numbers never start at 0; latent only, recorded so it is not rediscovered.
