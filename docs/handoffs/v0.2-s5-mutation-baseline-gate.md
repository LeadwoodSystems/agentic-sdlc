## Goal

Make a `RED-AS-PREDICTED` mean what it says: require `expectRed` to be absent from an
unmutated baseline run before a match in the mutated run is trusted — and re-anchor the
v0.2-s3 manifest whose three verdicts rested on hand-reasoning.

## The defect this closes

`classify()` searched the mutated run's whole `stdout + stderr` for `expectRed`. Under
`node --test` a **passing** test prints its title (`✔ <title>`), so an `expectRed` naming a
test was present in every run and the check collapsed into "did the exit code go non-zero" —
the check `expectRed` was written to replace. Not node-specific: any reporter that echoes test
names on success breaks the same way. Reasoning and the three rejected alternatives (failure-
region parsing, output diffing, documentation-only) in
`docs/superpowers/specs/2026-08-05-mutation-baseline-gate-design.md`.

The fix is a **precondition, not a smarter matcher**. `classify()`'s body is unchanged; what
changed is that its input is now proven discriminating before it is trusted.

## Key decisions & trade-offs

- **A precondition, not a smarter matcher.** Failure-region parsing was rejected because it
  hard-codes each framework's reporter format, breaking the tool's "knows nothing about any
  test framework" invariant — and a reporter change would revert it to today's behaviour
  without failing anything.
- **`BASELINE-RED` is a per-mutation verdict, not a thrown abort.** `runMutations` already
  continues past a bad anchor, and a red baseline belongs to one `testArgs` set. It exists to
  make `EXPECT-RED-INERT` sound: against a failing baseline, `expectRed`'s presence or absence
  is uninterpretable, and treating "absent" as "discriminating" there would manufacture the
  false confidence being removed.
- **No opt-out flag.** A gate with an off switch is off in the run whose result someone wants
  to believe.
- **`--dry-run` stays pure.** Its contract is "verify every anchor, run no tests"; a baseline
  is inherently a test invocation. The gate lives in the real run only.
- **A falsified v0.2-s3 verdict would have been recorded, not chased** (decided at plan time).
  Moot — all three held.

## Incidents worth carrying forward

**Two existing test fixtures broke or went hollow on the new precondition, and both were real
findings about the tests rather than about the gate.**
- `a test command that rewrites the source under test aborts the run` stubbed `status: 1` on
  every call, so the baseline now goes red and the run stops at `BASELINE-RED` before any
  mutation reaches disk — while the contamination it tests can only happen while one is
  applied. Fixed by making call 1 green; it still asserts the `DIRTY-REVERT` throw.
- `the runner receives testCommand followed by the mutation testArgs` kept passing but stopped
  proving its name: it stored only the *last* call, which had become the baseline. It now
  asserts both invocations exist and carry identical argv.

**A stub that returns one canned result for every call is the shape at risk.** Any future test
whose runner ignores call order now describes the baseline, not the mutation. Worth checking
first when a `mutate.test.js` test behaves oddly.

**The three v0.2-s3 target tests had no assertion messages**, so there was no failure-only text
to anchor on — Node's default diff was all they printed. Messages were added, then proven
absent from green output by grep *before* the manifest was written. The gate confirms it now,
but authoring order still matters: a bad anchor reports `EXPECT-RED-INERT` and costs a cycle.

**Reading the rendered doc caught an off-by-one the plan had introduced**: adding two verdicts
to `test-mutation-evidence.md`'s not-evidence list of four makes **six**, not five. The plan
said five. Prose counts get no gate — `asdlc-lint.js` lints `CLAUDE.md`, not `references/`.

## Deferred / known gaps

- **The gate removes the systematic false positive, not the coincidental one.** An anchor
  absent from the baseline can still be matched by an unrelated failure that happens to
  contain it. Judgment about blast radius stays with the reader, by design.
- **Full-suite wall clock is not a clean measurement.** Observed 50.7s → 77s → 73.8s → 29.1s
  across four runs today. The gate genuinely adds one subprocess per real-fixture test in
  `mutate.test.js`, but the last run came in *below* the pre-sprint baseline, so machine
  variance dominates. Do not quote a cost figure from this sprint.
- **`EXPECT-RED-INERT` could fire on a legitimate anchor** if a verbose reporter echoes the
  source line the anchor is about. Remedy is a more specific anchor; if it proves noisy that
  is a finding, not a reason to weaken the gate.
- **`checkpoint-hooks.js` writes LF into CRLF files** — found at this sprint's checkpoint.
  It hand-splices its marker span (`:57`, two literal `\n`) and appends the STATUS line
  (`:30`, one) without going through `lib/marker-block.js`. Measured: `CLAUDE.md` went
  CRLF=161/LF=0 → CRLF=159/LF=2, `STATUS.md` LF=0 → LF=1. `autocrlf` normalizes the index so
  nothing is corrupted, but it contradicts the Conventions rule in `CLAUDE.md` ("anything that
  rewrites a document must detect and preserve the dominant line ending"), which names only
  the two libs — and `checkpoint-hooks.js` is the third marker-span owner. Fix is to route it
  through `marker-block.js`; guard with a test asserting the rewritten file gains no LF.
- Carried from v0.2-s4, untouched here: `gaw` still has no `mutate.js` (needs a `gaw`-side
  re-bootstrap, plus the no-`.ps1`-port decision stated in its rule file); the
  `cancelled`/`skipped` conclusion predicate in `gh-hygiene.js`; the bootstrap guard's two
  holes (a stem-only list passes; `/lib\//` + `/test\//` check presence, not sense); the prose
  script-lists in `CLAUDE.md` (Stack & layout) and `skills/agentic-sdlc/SKILL.md`, both still
  omitting `mutate.js` and the three libs; `--limit 50`'s cost documented only in the plan.
- Carried from v0.2-s3: rider 2.3 (`size-sprint` upstream + mutation term) and 2.6
  (verification-log storage shape); missing `docs/superpowers/plans/_TEMPLATE.md`;
  `commands/sprint.md`'s wrong plan-naming scheme (it says `<date>-<sprint-id>-<slug>`; the
  canonical scheme is `vX.Y-sN-<slug>` and `new-sprint.js` pairs by slug); legacy
  `2026-07-22-loop-hardening.md` reporting `unmatched-plan`; `mutate.js`'s `main()` still
  untested; no `.ps1` ports.
