## Key decisions & trade-offs

- **Tier 2 matches inside the "Present the … findings (…)" parenthetical only**, not the whole
  file. The check set is written **twice** in `asdlc-hygiene.md` — the frontmatter
  `description:` and the findings sentence — and a whole-file match would pass when a label is
  deleted from the sentence but left in the description, i.e. the s8 bug surviving its own gate.
  The parenthetical is the instruction the agent executes. (Refinement made at plan time; the
  spec had said "case-insensitively in `commands/asdlc-hygiene.md`".)
- **The prose adopts the report's labels verbatim** rather than the gate matching fuzzily. The
  English is slightly more mechanical; in exchange there is no third vocabulary to maintain and
  the list names the exact lines the agent reads back.
- **`CHECKDROP` mutates the `label`, not the `key`** — corrected during this sprint, see below.

## Incidents worth carrying forward

**The spec's own `CHECKDROP` mutation was inert, and only running it revealed that.** Both the
spec (`:203`) and the plan specified renaming a `HYGIENE_CHECKS` **key** to simulate the script
drifting from the prose. It came back `GREEN`. The diagnosis is that the mutation was inert, not
the test hollow: the tier 2 gate compares **labels**, so a renamed key leaves the label list
complete and the test is *right* to stay green. Confirmed the other half too — a renamed key is
caught by `gh-hygiene.test.js` (4 failures), so it is not an undetected defect, merely outside
the prose gate's remit by design. Retargeting the mutation to the `label` field gave the
intended `RED-AS-PREDICTED` while keeping `HYGIENE_CHECKS.length` at 7, so the numeral assertion
stays green and the label assertion is isolated — which was the plan's stated reason for
renaming rather than deleting, just applied to the right field.

**Task 5 created a duplicate anchor for the mutation task that follows it.** Rewriting the
frontmatter `description:` to the same labels made `LABELDROP`'s planned anchor
(`stale merged branches, stale remote sprint branches, stale`) match **two** lines. The plan's
own step-1 uniqueness check caught it — as it did for s8's triple `process.exitCode = 1;` — and
the anchor now carries the `Present the seven findings (` prefix to disambiguate. **A plan that
edits a file in task N and anchors a mutation in it at task N+1 should expect this.**

**The byte-identical comparison flaked on the environment, not the refactor.** The first
`Compare-Object` showed the `Stale remote sprint branches` line differing — but as
`could not check (…)` from `git ls-remote` hitting the MSYS `add_item` crash and an askpass
failure, not a rendering change. Re-captured **both** sides under the token-header bypass
(`GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_0` env vars, so no token is written to `.git/config`), with
the pre-refactor file restored from `82a096b` for the "before" run: identical, both exit 0. **A
before/after diff spanning a network-touching check must have both halves captured under the
same auth conditions**, which the plan's "don't create branches in between" caveat did not
anticipate.

## Deferred / known gaps

- **Tier 1 shipped green — it caught nothing.** It is a regression guard for the v0.2-s4 failure
  mode, not a bug found. All 10 named paths already resolved.
- **The gate proves agreement, not correctness.** A label wrong in both the manifest and the
  prose passes. So does an inaccurate *description* of a script that exists (tier 1 checks
  existence only).
- **`asdlc-hygiene.md`'s frontmatter `description:` stays ungated.** Rewritten this sprint, but
  outside the findings parenthetical. Gating it needs a second, looser matcher — deliberately
  not done. It is now a verbatim duplicate of the gated list, so drift between them is possible
  and unchecked.
- **Only `asdlc-hygiene.md` has a tier 2 gate.** No other command declares its script's surface
  in a matchable form; nothing flags a script no command mentions.
- **Consumers get none of this** — `test/` is excluded from bootstrap by design. Consumer-side
  skew between a snapshotted `scripts/asdlc/` and live plugin prose was explicitly out of scope
  (needs `CLAUDE_PLUGIN_ROOT` + a version notion).
- **`NUMBER_WORDS` ends at twelve.** A thirteenth check fails with an explicit "extend the list"
  message rather than silently passing. Intentional.
- **`main()` in `gh-hygiene.js` is still untested** (carried from s8) — the refactored rendering
  is verified by the live diff and mutation, not a unit test.
- Carried from v0.2-s8, untouched: a re-run after a failed remote delete reads like a
  wrong-sprint-id error; both remote halves hardcode `origin`; `deleteBranch` result-shape
  assertions are partial; `parseLsRemoteHeads` drops a tab-less line.
- Carried from v0.2-s7 and earlier, untouched: `main()` in `mutate.js` untested by design;
  `runCli`'s `capture` seam only stubbed; `--test-name-pattern` anchors depend on a test-name
  substring; `FAILING_CONCLUSIONS` is a closed set; `appendStatusEntry` appends blindly; `gaw`
  has no `mutate.js`; the bootstrap guard's two holes; `--limit 50`'s cost documented only in a
  plan. From v0.2-s3: riders 2.3 and 2.6; no `.ps1` ports.
