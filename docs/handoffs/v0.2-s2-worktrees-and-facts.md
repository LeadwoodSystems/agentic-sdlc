## Key decisions & trade-offs

- **`git cherry` rejected as the no-GitHub fallback**, though the source doc proposed it.
  Measured against the real squash-merged branch it reported all 7 commits as `+`
  (unmerged) — a squash-merge produces one commit whose patch-id equals the *combined*
  diff. Adopting it would have reproduced the bug inside the fix. `git diff --quiet trunk
  branch` returns 0 correctly. Its documented failure mode: once trunk advances past the
  merge the trees diverge and it answers "not merged" — a false *negative*, the safe
  direction for a report-only audit, and the `gh` path covers it when a remote exists.
- **`run()` had to surface `err.status`.** `git diff --quiet` signals a *result* through
  exit 1; without the status it is indistinguishable from exit 128 (bad ref), and
  `gh-hygiene.test.js`'s existing "absent trunk must throw" assertion would have been
  silently downgraded to "reports a clean audit".
- **Ordering beats detail in `checkGate`.** Adding `detail` alone would not have fixed the
  masking — the plan check returned early. A stale *convention* must never hide a stale
  *resource*.
- **`marker-block.js` deliberately has one consumer.** `profile-block.js` and
  `checkpoint-hooks.js` were left on their own implementations; migrating them is a
  separate, riskier change.

## Incident worth carrying forward

`finish-sprint.js v0.2-s1 322ead8` **failed in real use**: it derived the branch as
`sprint/v0.2-s1` while the actual branch was `sprint/v0.2-s1-execution-profiles`
(`new-sprint.js` names branches `sprint/<id>` but plan/handoff files `<id>-<slug>.md`). It
had already rewritten `STATUS.md`, then died with a raw stack trace — half-applied and
non-idempotent, since the re-run fails in `markMerged`.

Fixed by `resolveSprintBranch` (exact-first, then `sprint/<id>-*` with the hyphen required
so `v0.2-s1` can't match `v0.2-s10`; refuses rather than guesses when several match), with
resolution moved **before** any mutation. The general lesson is the sprint's own thesis
applied one level up: *the script assumed a name instead of measuring it.*

## Deferred / known gaps

- **Stretch task 13 not implemented** — `gh-hygiene.js` has no failing-scheduled-workflow
  check. It is documented in `commands/asdlc-hygiene.md` as a manual `gh run list` step;
  replace that block with a sixth findings line when it lands.
- **`findStaleBranches` now spawns one `gh pr list` per sprint branch** instead of one
  `git log`. Correct but slower on a repo with many branches; a single
  `gh pr list --state merged --json number,headRefName` intersected locally is the cheaper
  shape.
- **A sprint branch with no commits yet reports as merged** (its tree matches trunk), so
  the gate won't block on it. Pre-existing snapshot semantics, not a regression — the old
  `git log` test behaved identically — but now worth knowing.
- **The legacy `docs/superpowers/plans/2026-07-22-loop-hardening.md`** predates the naming
  convention, so it will report `unmatched-plan` forever. Rename it or accept the noise.
- **No PowerShell ports** for `facts.js`, `asdlc-lint.js`, `branch-status.js`,
  `marker-block.js`. GAW runs `.ps1`. Decide port-vs-invoke-the-JS before GAW adopts these.
- **`checkpoint-hooks.js` still has no `.ps1` port** (carried from v0.2-s1).
