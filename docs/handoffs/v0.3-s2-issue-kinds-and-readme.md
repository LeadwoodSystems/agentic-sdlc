### Step 2: claim inventory

#### Title / intro (top matter, before "## The problem")

- [ ] Agentic SDLC is a Claude Code plugin
- [ ] it is a spec-driven, checkpoint-gated build loop
- [ ] it is for driving large, multi-session AI software builds without losing context, handoffs, or history
- [ ] core principle: keep persistent context thin, push history to disk, make every sprint resume-ready from a written handoff
- [ ] proven across 100+ sprints on one product
- [ ] this plugin orchestrates the `superpowers` skills (brainstorming, writing-plans, test-driven-development, verification-before-completion, requesting-code-review) — it does not replace them

#### The problem

- [ ] Agentic SDLC exists to answer one question cheaply: "where were we, and what do I do next?"

#### The two rules

- [ ] Rule 1: `CLAUDE.md` holds only durable rules and architecture, target under ~200 lines, never a changelog
- [ ] Rule 1: running history lives in `docs/STATUS.md`
- [ ] Rule 1: current state lives in the **latest** `docs/handoffs/` file
- [ ] Rule 2: checkpoint sequence is plan (before) → build test-first → verify with evidence → handoff (after) → commit → stop for human approval → `/clear`
- [ ] Rule 2: one unit of work per checkpoint

#### The loop, per sprint

- [ ] Step 1: Plan → `docs/superpowers/plans/` (brainstorm → write the plan)
- [ ] Step 2: build test-first
- [ ] Step 3: verify with real evidence — commands run, live output, test counts, not assertions
- [ ] Step 4: adversarial review is *offered* when the diff or issue warrants it (security surface, auth, data handling, wide blast radius), with its rough cost stated — never mandatory, because a review that fires on every sprint and can't run in a subagent-less session produces a merge-blocking decision instead of a review, which is why that mandate was retired
- [ ] Step 5: handoff → an evidence-bearing `docs/handoffs/<sprint>.md` so a fresh session can resume exactly here
- [ ] Step 6: checkpoint → tests pass, handoff exists, `docs/STATUS.md` updated, commit staged, then stop for approval and `/clear` before the next sprint

#### Commands (every table row)

- [ ] `/bootstrap-asdlc` — scaffold this workflow into a new (or existing) repo
- [ ] `/verify-issue [id]` — adversarially check a tracked issue against the codebase before it becomes a plan
- [ ] `/profile-issue [id]` — assess an issue and attach an Execution Profile: complexity, risk, and per-phase routing
- [ ] `/sprint [name]` — start a sprint: runs the sprint gate, scaffolds its plan, kicks off brainstorm → plan
- [ ] `/checkpoint` — non-blocking gate: tests + handoff-exists + STATUS/CLAUDE.md pointer script, then stage
- [ ] `/handoff` — generate an evidence-bearing handoff from the template
- [ ] `/asdlc-hygiene [trunk] [version]` — on-demand audit: stale branches, stale worktrees, default-branch drift, untriaged issues, milestone/version sync

#### State model — one source of truth (every table row + prose)

- [ ] Durable tier lives in `CLAUDE.md`: architecture, rules, gotchas — read every session, in full
- [ ] History tier lives in `docs/STATUS.md`: append-only, **machine-generated only** (never hand-edited)
- [ ] Current-state tier lives in the latest `docs/handoffs/*.md`: status, evidence, follow-ups — read at session start
- [ ] exactly one source of truth for "where things are": the newest handoff — don't hand-sync the same status into `CLAUDE.md`, memory, and a handoff, because that drifts
- [ ] numbers are measured, not typed: every count, timing and port `CLAUDE.md` asserts is declared in `.asdlc/facts.json` as a *command to run*
- [ ] `scripts/asdlc/facts.js` executes those commands and owns the `<!-- asdlc:facts:auto -->` span
- [ ] a command that fails writes `**UNMEASURED**` with the reason rather than leaving the old value, because a stale number that looks freshly measured is worse than no automation
- [ ] `scripts/asdlc/asdlc-lint.js` fails when: the facts block is absent or stale, a retired rule is still holding a numbered slot, a rule runs past ~120 words, or two of the file's own assertions contradict each other
- [ ] operating rules carry stable slugs, not numbers — cite `#git`, not "rule 2"
- [ ] numbering would mean a retired rule must be embalmed in its slot forever so old citations keep resolving; with slugs it is simply deleted and a stale citation fails loudly
- [ ] one sprint = one worktree = one session: a branch can be checked out in exactly one working tree at a time
- [ ] the worktree — not the session — is the safe unit of concurrency: two sessions in one directory fight over HEAD, two sessions in two worktrees cannot
- [ ] `new-sprint.js` refuses to start a sprint over a stale worktree
- [ ] `finish-sprint.js` removes the worktree before deleting the branch
- [ ] `/asdlc-hygiene` audits for orphan worktrees
- [ ] plans and handoffs share one naming scheme: `vMAJOR.MINOR-sN-<slug>.md`
- [ ] when a milestone closes, run `node scripts/asdlc/archive-sprint-docs.js <milestone>` to move each type's files into its own `archive/<milestone>/` subdirectory (`docs/handoffs/archive/<milestone>/`, `docs/superpowers/plans/archive/<milestone>/`) so the live directories stay small

#### Works for solo devs and small teams — it's just GitHub

- [ ] no new tooling required — the loop rides directly on GitHub primitives already in use
- [ ] the primitive chain is Issue (the spec) → Branch (one working line) → Commit (one clean checkpoint) → PR (where review happens) → Main (the reviewed baseline)
- [ ] solo devs review their own PR before merging — the pause is the point
- [ ] on a small team, that's where a teammate looks

#### Installing

- [ ] local install: `/plugin marketplace add /path/to/agentic-sdlc` then `/plugin install agentic-sdlc@leadwood-local`
- [ ] once public, remote install: `/plugin marketplace add LeadwoodSystems/agentic-sdlc` then `/plugin install agentic-sdlc@leadwood-local`

#### Common mistakes (every bullet)

- [ ] hand-editing `docs/STATUS.md` or `CLAUDE.md`'s current-state line is a mistake — let `scripts/asdlc/checkpoint-hooks.js` own both; hand-edits are exactly what caused drift in real usage
- [ ] skipping the handoff "to save time" is a mistake — the next session can't resume; this is the one step never to cut
- [ ] pushing straight to `main`, or bundling many sprints into one PR, is a mistake
- [ ] running two sessions in the same working tree to get parallelism is a mistake — they fight over HEAD; one worktree per sprint, retired when the sprint ends
- [ ] the orphan-worktree incident: an orphan worktree survived a week at 1.15 GB holding 14 uncommitted files nobody could see
- [ ] typing a test count, timing, or port into `CLAUDE.md` is a mistake — it's wrong within weeks and still reads as authoritative; declare it in `.asdlc/facts.json` and let `facts.js` measure it
- [ ] letting merged sprint branches or worktrees pile up, or milestones drift from the sprint version scheme, is a mistake — run `/asdlc-hygiene` periodically to catch all three
- [ ] hard-blocking hooks for routine actions is a mistake — prefer non-blocking helper commands
- [ ] `new-sprint.js`'s gate is the one deliberate exception: it *does* hard-block starting a new sprint on top of an uncommitted one, because that specific failure mode was observed in practice and is deliberately not advisory
