## Key decisions & trade-offs

- **The exemption is an explicit allowlist, not the `kind/` prefix** — decided by the final
  review, after the prefix had already shipped in `f3f2fad`. The prefix was reached for by
  analogy to `PROFILE_LABEL_PREFIXES`, and that analogy does not hold: `complexity/` names
  one axis whose *buckets* may grow, so prefix-matching avoids coupling to the bucket list;
  `kind/` names only "this issue has a type", which is not the predicate being tested. The
  predicate is "is never executed directly", and that is not derivable from the string. What
  decided it is the consumer: this script ships, and `/bootstrap-asdlc` scaffolds it into
  **existing** repos, where `kind/bug` / `kind/feature` / `kind/cleanup` (the Kubernetes
  convention) is one of the most widespread taxonomies on GitHub. An open prefix would have
  silently removed every bug and feature from such a repo's profiling worklist — a worklist
  that reads as complete and is not, which is the exact failure class v0.3-s1 existed to
  eliminate. A one-line saving here against a silent, unrecoverable under-report there.
  A regression test pins it, and the design doc now records the prefix as a rejected
  alternative.
- **`kind/decision` is on the allowlist already**, ahead of #33. It is the case the mechanism
  was designed for and #37's body names it, so listing it recovers the prefix's one real
  benefit — the other half of #37 stays a tracker action — without the blast radius.
- **The finding is named `epic-without-open-sub-issues`, not `epic-without-sub-issues`.** The
  call is `--state open`, so the parent set can only prove an epic has *open* children. An
  epic whose children have all been closed **will** be flagged, and the name says exactly
  why rather than claiming the epic has no children. That is a useful signal in its own
  right. Same convention as `facts.js`'s `**UNMEASURED**` and `staleRemoteBranches`'
  `unjudged:` — a check states what it measured, never what it wished it could measure. A
  second `--state all` call was rejected: a second network call and a second truncation
  surface, in a function that spent all of v0.3-s1 being made honest about one call's limits.
- **The README has 12 `##` headings, not 15.** Slots 3 (Before/With), 6 (deterministic vs
  agentic) and 7's 60-second walkthrough belong to #18, #19 and #21 and were left **absent,
  not stubbed**. An empty heading reads as a documentation bug to every reader who arrives
  before those issues land. The acceptance criterion is that the README *follows* the
  ordering — the sections that exist appear in the epic's relative order (slots 1, 2, 4, 5,
  7, 8, 9, 10, 11, 12, 13, 14, 15, strictly ascending), and each absent one has a named
  owner. Recorded because a reviewer counting headings will find 12.
- **GitHub native Issue Types were ruled out, not overlooked.** `gh issue list --json`
  exposes `issueType`; it returns `null` for all 46 open issues because this repo has never
  configured them, and doing so is org-level tracker configuration, not a script change.
- **`#37`'s own premise is overstated and is corrected on the tracker.** Its Scope warns that
  an exemption "lets a whole class of issue escape all hygiene checks". It does not:
  `no-labels` and `no-milestone` still apply, and a `kind/epic` label satisfies neither by
  accident. Only `no-execution-profile` is skipped, and one test pins that.
