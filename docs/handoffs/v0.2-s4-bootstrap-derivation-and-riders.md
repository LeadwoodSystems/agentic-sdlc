## The finding that reshaped the sprint

**`gaw` has no `mutate.js` because `bootstrap-asdlc.md`'s file list went stale, not because
of the no-`.ps1`-port decision.** The plugin distributes scripts by **copy-into-repo**: step 6
of `commands/bootstrap-asdlc.md` names what a consuming repo receives. It named **11** files
while **15** exist. The four missing ones — `mutate.js`, `lib/apply-mutation.js`,
`lib/manifest.js`, `lib/report.js` — are exactly v0.2-s3's output. The sprint that built the
tool never updated the manifest that hands it to consumers, so no amount of telling `gaw`
about the port decision would have delivered a file bootstrap does not copy.

Fixed by **deleting the enumeration and deriving it**, guarded by a test. Reasoning and both
rejected alternatives in `docs/superpowers/specs/2026-08-05-plugin-consumption-and-riders-design.md`.

## Key decisions & trade-offs

- **Delete the list, don't correct it.** Fixing the list + a two-way test keeps two sources of
  truth in sync by gate — the shape `#ports-are-prose` already bans for numbers. A list of
  files typed into prose is the same smell, and it has now failed once. A derivation can't go
  stale. `.asdlc/bootstrap-files.json` rejected on YAGNI: it buys deliberate exclusions, and
  no file needs excluding.
- **`${CLAUDE_PLUGIN_ROOT}` is rejected for paths *inside* copied scripts, and required as
  the copy *source*.** Consumers own the files once bootstrapped, so a reference back to the
  plugin's install location would break when the plugin is removed. But step 6 says where to
  copy *from*, and a bare `scripts/asdlc/` there resolves to the consumer's own tree — an
  agent copies nothing and reports success. The spec now distinguishes the two uses.
- **Filter scheduled runs server-side (`--event schedule`).** The command's old prose used
  `--limit 40` over all events; on a busy repo a weekly workflow falls off the end and reads
  as absent — the silent-skip class `mutate.js` exists to refuse.
- **Skip in-flight runs rather than guessing.** `status !== 'completed'` has no conclusion.
- **`plan-template.md` riders get no test.** `asdlc-lint.js` lints `CLAUDE.md`, not
  references; a lint rule guarding two sentences costs more than it protects.

## Incidents worth carrying forward

**`expectRed` was pointed at test *titles*, which voids the reason-check — and it affects
v0.2-s3 too.** `node --test` prints a test's title when it **passes** (`✔ <title>`), and
`classify()` (`mutate.js:75-82`) does a substring check over the whole output. So an
`expectRed` that is a test title is present unconditionally, and **any** non-zero exit from
that file classifies as `RED-AS-PREDICTED`. The pattern was borrowed from a pytest example
where the string is a docstring — printed only on failure — and it degrades silently under
`node:test`. Both v0.2-s4 anchors were re-pointed at assertion failure messages, each proven
absent from passing output by grep before use. **`docs/mutation-manifests/v0.2-s3.json` still
has three title-based `expectRed` values, so its verdicts carry the same asterisk.** Found by
the whole-branch review, not by the tool.

**The plan repeated the very defect the sprint was fixing.** Task 3's brief enumerated four
`runHygieneAudit` stubs to update; there were five. The implementer caught it and was told to
apply the rule rather than the list. A plan that fixes a stale enumeration by writing another
stale enumeration is worth remembering.

**Fixing one finding broke another's anchor.** Naming the copy source rewrote the exact line
`ENUM.find` targeted, so `--dry-run` reported `ANCHOR-MISS` and the manifest needed a second
commit. A text-anchored manifest and the prose it targets are coupled — a future editor of
step 6 must check `ENUM.find` too.

**The `Edit` tool wrote LF into two CRLF files** (`v0.2-s4.json`, the spec) and was caught by
git's `LF will be replaced by CRLF` warning on `add`, then corrected via
`[System.IO.File]::ReadAllText/WriteAllText`. `git ls-files --eol` confirms the index is `lf`
for all files, which is what `autocrlf` wants — but don't assume `Edit` preserves CRLF here.

## Deferred / known gaps

- **`gaw` still has no `mutate.js`.** This sprint fixed the *instruction*; it did not verify
  delivery. `gaw` must re-bootstrap — a `gaw`-side sprint. The no-`.ps1`-port decision still
  needs stating where `gaw` reads it (one line in its rule file, not a delivery mechanism).
- **`classify()` reason-checking under `node:test`** — the manifest anchors are fixed, the
  tool is not. Cross-language problem; scope it with `references/test-mutation-evidence.md`,
  whose worked example teaches the pytest pattern that fails here. Re-anchor
  `docs/mutation-manifests/v0.2-s3.json` in the same sprint.
- **`cancelled` / `skipped` conclusions are reported as failures.** `conclusion !== 'success'`
  is the predicate, while `asdlc-hygiene.md` says "treat a finding here as a real red, not as
  noise." Either narrow to `failure`/`timed_out`/`startup_failure`/`action_required`, or soften
  the prose.
- **The bootstrap guard has two holes:** a stem-only list ("copy `new-sprint`,
  `checkpoint-hooks`…") passes, and `/lib\//` + `/test\//` check presence, not sense —
  "excluding `lib/` and including `test/`" passes all three assertions.
- **Prose script-lists survive in `CLAUDE.md` (Stack & layout) and `skills/agentic-sdlc/SKILL.md`**
  — both still omit `mutate.js` and the three new libs, the *identical* v0.2-s3 omission.
  Neither strands a file (they're maps, not delivery manifests), but the spec's own argument
  applies to them.
- **`--limit 50`'s cost is documented only in the plan**, not at the code.
- Carried from v0.2-s3: **rider 2.3** (`size-sprint` upstream + mutation term) and **2.6**
  (verification-log storage shape); missing `docs/superpowers/plans/_TEMPLATE.md`;
  `commands/sprint.md`'s wrong plan-naming scheme; legacy `2026-07-22-loop-hardening.md`
  reporting `unmatched-plan`; `mutate.js`'s `main()` still untested; no `.ps1` ports.
