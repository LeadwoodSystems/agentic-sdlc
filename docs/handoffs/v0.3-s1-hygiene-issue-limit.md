## Key decisions & trade-offs

- **Raised bound + cap detection, not `gh api --paginate`.** The REST `/issues` endpoint
  returns pull requests too, so paginating would need `pull_request`-key discrimination and
  field remapping — new logic and new bug surface inside a straight bug fix. The bound stays;
  the cap check is what stops it lying. Three further alternatives are recorded as rejected in
  the spec, including a synthetic in-array `result-truncated` entry (would have mixed facts
  about issues with facts about the audit) and throwing on cap (would discard findings already
  collected, against this file's stated "tell the human as much as you can find out").
- **`>=`, not `===`.** Since `gh` cannot return more than `--limit`, the two differ only at
  exactly 1000, so the choice is purely which error to make there. The notice says "**may** be
  incomplete", so it is not really a false alarm — it is an accurate statement of uncertainty.
  Recorded so nobody "fixes" it.
- **Truncation does not set `process.exitCode = 1`.** Exit 1 in this script means *a check
  could not run*. Conflating would destroy a caller's ability to tell "gh is unauthenticated"
  from "you have a lot of issues" — two situations demanding opposite responses. If CI ever
  needs truncation to fail a build, that is a distinct code 2, not this one.
- **The return shape changed** (`array` → `{findings, truncated}`), which supersedes #57's own
  AC bullet "existing cases still pass unmodified". The behaviour those cases assert is
  preserved exactly; only their shape moved.

## Incidents worth carrying forward

**#57's own proposed regression test was inert, and the design caught it before it was
written.** The issue asked for "46 stubbed issues, 39 unprofiled → all 39 reported (fails on
today's code)". It does **not** fail on today's code: the stub runner ignores its arguments, so
it cannot reproduce a server-side cap — the defect was the *absent argument*. The regression
test therefore asserts on the arguments the runner receives. **#57's AC bullet 6 still needs
correcting on the tracker** (see Deferred).

**The sprint's own headline behaviour shipped untested until the final review caught it.** The
truncation test stubbed 1000 *fully profiled* issues, so `findings` came back empty and only
`none · TRUNCATED: …` was ever exercised. `format` could have been rewritten to blank the
findings when truncated — exactly the alternative the spec argued hardest against — and every
test would still have passed. The gap also left two Global Constraints (exact notice text,
exact `' · '` separator) unpinned, since only `/TRUNCATED/` was asserted. Fixed with one pure
full-string assertion, no fixture repo. **A test whose fixture makes the interesting field
empty is testing the uninteresting case**; the plan specified that fixture and neither the
task review nor the mutation manifest caught it, because all three agreed with each other.

**The plan shipped a wrong mutation prediction.** `CAPBLIND.expectRed` was written
`"true !== false"`; the suite imports `node:assert/strict`, so `assert.equal` aliases
`strictEqual`, whose message is `${actual} !== ${expected}` — i.e. `false !== true`. It
surfaced as `RED-WRONG-REASON` on the first real run and was diagnosed rather than papered
over. Corrected in both the manifest and the plan.

## Deferred / known gaps

- **Two corrections owed to #57 on the tracker** (not yet pushed): AC bullet 6's inert
  regression test, and "existing cases still pass unmodified", superseded by the shape change.
- **#37 lands next in this same function** (`findUntriagedIssues` and its tests) and must be
  told the return shape is now `{findings, truncated}`. Its own body already says to land #57
  first.
- **`isCheckError` types by key *arity*** (`'error' in value && Object.keys(value).length === 1`,
  `gh-hygiene.js:416-419`). Safe today — the new shape clears it by two margins, and a test
  pins that — but it is one careless future return away from misclassifying a real result as
  "could not check". A branded `Symbol`/`class CheckError` would harden it. Natural to bundle
  with #37, which touches this area.
- **The three fixture-repo truncation tests never touch the filesystem.** The stub runner
  ignores `cwd`, so they pay `makeFixtureRepo`'s ~80× bootstrap for nothing, recompounded on
  every mutation run. Deliberately not fixed: a performance refactor of green, just-reviewed
  tests that the mutation manifest cites, deferred rather than done minutes before merge.
- **`NOTICEDROP`'s `expectRed: "TRUNCATED"` is loose** — it matches any failure of that
  `assert.match`. Judged harmless: `mutate.js`'s `EXPECT-RED-INERT` guard already proves the
  literal is absent from a green run, and `CAPBLIND` aborts at an earlier assertion so it
  cannot emit it either. Same looseness exists in the accepted v0.2-s9 manifest.
- **`Milestone/sprint version sync` reports OUT OF SYNC (milestones: )** — pre-existing, out of
  scope, carried from the roadmap. The check looks for a `vX.Y` token and this milestone has
  none. Still undecided whether to file.
- Carried from v0.2-s9, untouched: `asdlc-hygiene.md`'s frontmatter `description:` stays
  ungated; only `asdlc-hygiene.md` has a tier 2 gate; `main()` in `gh-hygiene.js` still
  untested; consumers get no prose gate. From v0.2-s8 and earlier: remote-delete re-run reads
  as a wrong-sprint-id error; both remote halves hardcode `origin`; `parseLsRemoteHeads` drops
  a tab-less line; `mutate.js`'s `main()` untested by design; `gaw` has no `mutate.js`; the
  bootstrap guard's two holes; no `.ps1` ports.
