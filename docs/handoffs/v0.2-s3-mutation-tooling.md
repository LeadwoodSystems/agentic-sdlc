## Key decisions & trade-offs

- **`testCommand` is an argv array, not a string** (diverges from the source proposal's
  example). A string needs `shell: true` — `cmd.exe` on Windows, `/bin/sh` elsewhere — and a
  mis-split command surfaces as `RED-WRONG-REASON`, i.e. as a *finding* rather than as
  tooling failure. `parseManifest` rejects the string form by name.
- **Per-mutation `testArgs`, not `target` + `filter`.** The proposal's `filter` is `-k`,
  which is pytest syntax; this repo could not have dogfooded on its own `node:test` suite.
- **No `.ps1` port — ever.** `gaw` invokes `node mutate.js`. A port re-imports precisely the
  encoding hazards the tool exists to remove. Recorded in the spec so it isn't hand-ported
  by reflex; **`gaw` has not yet been told this.**
- **`runCapture()` is a second function, not an option on `run()`.** The v0.2-s2 handoff
  records how close a flag on that path came to silently downgrading `gh-hygiene`'s
  "absent trunk must throw" assertion.
- **`AMBIGUOUS-ANCHOR` added to the vocabulary.** The proposal is silent on a `find` that
  matches twice, so the default would be "mutate the first" — a verdict that reads as
  evidence and isn't.
- **The proposal's line-ending rule was wrong and is corrected in the spec.** Normalizing
  the whole source and re-emitting promotes lone `\n` to `\r\n` in a mixed-ending file,
  changing bytes outside the mutation and causing a `DIRTY-REVERT` the tool itself caused.
  Convert the *anchor* into the file's ending instead; everything outside the match is then
  byte-identical by construction.
- **Bad anchors don't abort the run** (reading of proposal §1.4.3). Anchors are authored
  blind and fail in batches; aborting on the first makes a 12-mutation manifest cost 12
  cycles. The run is still marked not-evidence.

## Incidents worth carrying forward

**A uniformly-GREEN run was a broken instrument, not hollow tests.** Three integration tests
failed on the first run, all classified `GREEN`. Cause: `node --test` sets
`NODE_TEST_CONTEXT` in its children; a nested `node --test` inherits it, reports over IPC,
and **exits 0 with empty output**. Every mutation therefore read as "this test is hollow"
— the exact false finding the tool exists to prevent, arriving inside the tool's own suite.
Fixed by removing the nesting from the fixture rather than working around it; documented in
`references/test-mutation-evidence.md` under "two traps".

**A hollow test caught during RED.** `runCapture() still throws when the binary does not
exist` passed while `runCapture` was still undefined — calling `undefined` throws a
`TypeError`, and a bare `assert.throws()` accepts any throw. Tightened to assert
`err.code === 'ENOENT'`. It only surfaced because each module was stubbed so every test
failed on its *own* assertion, rather than accepting one `MODULE_NOT_FOUND` as the RED.
**Keep that habit** — a stub-then-RED pass is how the negative-space tests get audited.

**The reporter claimed work it hadn't done.** The first real CLI run printed "Reverts
verified clean" after a `--dry-run` that never wrote anything, and tagged `ANCHOR-OK` with
the `!!` action marker. Both found by *running* the tool, not reading it (`2298d68`).

## Measured: the bootstrap tax is real here too

Finding 2.2 reproduced in this repo. Same manifest, same run: the two library mutations
cost **0.2s** each; the one targeting `mutate.test.js` cost **16.7s** — ~80×, because that
file builds real git fixture repos. The multiplier lands in the mutation loop, which pays
it once per run. This is the concrete argument for the deferred `plan-template.md`
test-tier note.
