## The defects this closes

**`checkpoint-hooks.js` wrote LF into CRLF files on every checkpoint.** It hand-spliced its
marker span (two literal `\n`) and appended the STATUS line (one) without going through
`lib/marker-block.js`. `CLAUDE.md`'s Conventions rule requires any document rewriter to detect
and preserve the dominant line ending and named only two libs; `checkpoint-hooks.js` is the
third marker-span owner. `autocrlf` normalised the index, so nothing was corrupted and no test
noticed — which is why the fix needed a byte-level assertion rather than a behavioural one.

**The command surface was not dogfooded at all.** `~/.claude/commands/` held loose copies from
`092bcdd` (initial commit): `asdlc-hygiene.md` and `profile-issue.md` were **never installed**,
`bootstrap-asdlc.md` and `checkpoint.md` differed by 49 lines, `sprint.md` by 15.
`.claude-plugin/{marketplace,plugin}.json` already existed and pointed at `./` — the plugin was
simply never enabled. **This sprint's own `/sprint` invocation skipped the `new-sprint.js` gate
step** because the installed copy has no such step; the gate was run by hand afterwards.

## Key decisions & trade-offs

- **`asdlc-lint.js` was not extended.** It argues for a one-file scope at `:206-218` and names
  cross-file disagreement as explicitly out of bounds; adding disk-derived checks would make
  that paragraph false. `facts.js` is not the alternative either — `summarize()` caps a fact at
  one line / 120 chars, so a 15-name list truncates. **The enumerations were deleted rather
  than gated**, which is the v0.2-s4 derive-don't-enumerate argument taken to its end.
- **No `plans/_TEMPLATE.md` was added here.** A copy of `references/plan-template.md` is a
  second file that drifts; the resolution order gives the same result with nothing to drift.
  Consumers keep the bootstrap-written copy and are unaffected.
- **`upsertBlock`'s append-when-absent is deliberately not inherited.** The current-state
  pointer's position in `CLAUDE.md` carries meaning, so `updateClaudeMdPointer` keeps its own
  `found` check and refuses. Delegating everything would have been tidier and wrong.
- **A newly created `STATUS.md` gets LF, not `os.EOL`** — guessing from the host OS would
  impose a house style on repos that do not use one, and `autocrlf` normalises LF anyway.
- **`profile-block.js` stays unmigrated** — its ``` fence guarding is behaviour `upsertBlock`
  does not reproduce. Named in `marker-block.js` so the next reader knows it is a decision.

## Incidents worth carrying forward

**The v0.2-s5 handoff was wrong about `commands/sprint.md`.** It carried "wrong plan-naming
scheme (`<date>-<sprint-id>-<slug>`)" as an open item. That file was fixed in `6a5d616`; the
stale text was in the *installed copy*. A backlog item can name the wrong artefact when two
copies of a file exist and only one is read — **check which copy is live before believing a
carried finding.** Finding this is what turned a four-item cleanup into Task 2.

**A plan's line count can be wrong about its own target.** The plan named four `split('\n')`
sites in `checkpoint-hooks.test.js` (citing the *assertion* lines `:88,:109,:130,:151`); there
are five split sites at `:62,:83,:104,:125,:146`, plus one more at `:42`. All six were
repaired. Cite the line you intend to edit, not the line that motivated the edit.

**`asdlc-lint.js` goes red mid-sprint by design and it is not a failure.** Adding tests moves
the count before `facts.js` runs, so the lint reports a stale facts block from the first
test-adding commit until Task 6. Expect it; do not "fix" it early by hand-editing the span.

**`mutate.js` refuses to run with an uncommitted manifest.** The manifest must be committed
before its own dry-run — an ordering the plan did not state and which costs one cycle to learn.
